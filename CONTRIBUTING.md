# Contributing to Jarvis Homelab

Thank you for your interest in Jarvis.

Jarvis is currently a personal home-lab project and a **public development journal**. The long-term aim is to make the build easier for others to reproduce, with a possible open-source software release when code, installation steps, and a license are ready. It is **not yet a packaged application or an open-source code release**.

## Ways to help now

- Read the [README](README.md) and [development log](docs/progress/2026-11-05-to-10.md), and point out unclear steps or factual errors.
- Suggest affordable, maintainable hardware and ways to reuse older equipment.
- Share relevant experience with Proxmox, Debian, PostgreSQL, FastAPI, Piper, Home Assistant, backup and recovery, or home-automation security.
- Propose focused tests and clear acceptance criteria, especially for voice, memory, backups, and integrations.
- Share the project with others who might learn from it. Financial contributions are not required.

## Proposing an improvement

Before implementing anything, describe:

1. The problem or limitation you want to address.
2. What you propose and why.
3. Hardware, software, and external-service requirements.
4. How the result could be tested and documented.
5. Any privacy, security, operating-cost, or maintenance trade-offs.

If GitHub issues are enabled, open a focused issue. Otherwise, use the repository's available public discussion or contact channels once established. Avoid posting sensitive configuration or personal information.

## Current technical boundaries

This repository is a record of progress, not evidence that each experiment is currently operational. Please distinguish **tested**, **reported working**, **prepared**, and **planned** capabilities. Do not describe an integration as complete until it has been checked end to end.

Jarvis currently uses external AI services for some functions. Please do not assume everything is offline, free to operate, or ready for installation on a different computer.

## Safety and privacy

Never publish passwords, API tokens, private keys, access credentials, personal conversation history, device identifiers, private network details, or unredacted backups. Do not paste live secrets into issues or pull requests. For suspected security problems, avoid exposing exploit details or credentials in a public issue; request a private reporting method first.

## Licensing and code contributions

**No software license has been selected yet.** A public GitHub repository is not automatically an open-source software release, and access to read the repository does not automatically grant permission to redistribute code.

Before accepting reusable code contributions or publishing a source release, the project needs a clear license, contribution terms, and a review for secrets and other sensitive material. For now, documentation corrections and focused proposals are the most useful starting points.

## Optional support

If you want to support hardware, testing, and documentation costs, see the [optional GoFundMe campaign](https://gofund.me/778e57dbd). Donating is not required to participate and is not a purchase, investment, or guarantee of a future release.
